# ハーネス・ワークス(仮)

ベテラン頼みの製品設計業務を、AIエージェントとハーネスで自動化し、24週間で利益を最大化するブラウザ向け経営シミュレーション。
LLM の挙動は確率モデルによる擬似再現で、外部 API は呼びません。

## 遊び方(開発環境)

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # dist/ に静的ファイルを出力(どの静的ホスティングにも置ける)
npm test           # Vitest(計算式・週次シミュレーションの単体テスト)
npm run headless   # バランス検証(3戦略 × 1,000回)。回数は `npm run headless -- 200`
```

## 構成

```
src/
  core/    画面に依存しない計算(React を import しない)
    types.ts  rng.ts  formulas.ts  simulateWeek.ts  events.ts  scoring.ts
    actions.ts  計画フェーズの操作(検証付き・state を書き換えない)
    init.ts     初期状態   tags.ts  原因タグの表示名
  data/    ゲームデータ。数値はすべてここ(balance.ts に調整用の値を集約)
  store/   gameStore.ts(Zustand。core を呼ぶだけ。localStorage に毎ターン自動保存)
  ui/      screens/(タイトル・ライン・人員配置・カンコツ図鑑・週次レポート・最終結果)
           components/(工程詳細パネル・開発キュー・実行演出・遊び方 ほか)
scripts/
  strategies.ts  自動プレイ戦略(何もしない/全工程に大モデル/模範プレイ)
  headless.ts    バランス検証
tests/
```

`simulateWeek(state)` は純粋関数で、乱数は `state.seed` から生成し次のシードを返します。同じ初期シードと同じ操作列からは必ず同じ結果になります(テストで保証)。

## バランス検証の結果(1,000回)

| 戦略 | 最終資金の中央値 | 期待 | 判定 |
| --- | --- | --- | --- |
| 何もしない | 1,000万円 | 950〜1,100万円 | ✅ |
| 全工程に大モデルを素で配備 | 4週目までに全回プロジェクト中止 | 何もしないを下回る | ✅ |
| 模範プレイ | 3,006万円(A以上 91%、S 50%) | Aランク以上 | ✅ |

## 仕様書からの調整・解釈

- **調整した数値**(`src/data/balance.ts`)
  - 固定費 40 → 33万円/週、納期内出図の評判 +0.5 → +0.8:3条件を満たすための調整。
  - 受注残の上限 8 → 12件:上限8だと週10件の処理ができないため。
- **解釈した点**
  - 開発は着手した週の終わりに1週ぶん進む。1週の部品は翌週から有効、開発枠もその時点で空く。
  - 承認ゲートは工程ごとのON/OFF。レビューは人員配置で「承認レビュー」コマを割り当てた人が行い、1コマ8件まで確認する。
  - 重大事故が起きた週は、ライン全体の工程処理が止まる(受注と費用計上は行う)。
  - 設計レビューで複数の不良が見つかった案件は、該当工程を順にやり直してから工程6に戻る。
  - 「失敗から学ぶ」のミス累計は、ログ監視の設置後に数える(検証ループや承認ゲートで拾えたミスも含む)。
  - 人の担当工程の成功率は人数のコマ数で加重平均。人の成功率は評価ベンチがなくても表示する。
  - 役員の一声(第1週)を受けると、工程4がその週だけ大モデルになり、翌週は元の担当に戻る(称号「小さな巨人」の判定には含めない)。
